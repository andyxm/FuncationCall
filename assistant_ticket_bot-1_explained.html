assistant_ticket_bot-1.py —— 代码讲解与逻辑图

基于 Qwen-Agent 的「门票订单分析助手」：用 Function Calling 让大模型自动写 SQL 查 MySQL

一、这个脚本在做什么？（一句话）

它把 Qwen 大模型 包装成一个「门票助手」：用户用自然语言提问（如“各周门票销量多少”）， 大模型借助 Function Calling 自动生成 SQL，调用 exc_sql 工具去远程 MySQL 查 tkt_orders 表， 再把返回的数据用自然语言总结给用户。提供 网页 GUI 和 终端 TUI 两种交互方式。

三、代码逐块讲解

1. 导入与全局配置（第 1–16 行）

  • dashscope：阿里灵积（通义千问）SDK；dashscope.api_key 从环境变量 DASHSCOPE_API_KEY 读取。
  • qwen_agent.agents.Assistant：智能体封装；qwen_agent.gui.WebUI：Gradio 网页界面（正是之前缺失 GUI 依赖报错的地方）。
  • BaseTool / register_tool：Qwen-Agent 自定义工具的基类与注册装饰器。
  • ROOT_RESOURCE：资源文件根目录（本脚本未实际使用图片，仅占位）。

2. system_prompt（第 18–47 行）—— 给大模型的“说明书”

这是整个助手能力的核心。它把 tkt_orders 表的 建表语句 + 字段含义 直接写进提示词， 并额外告诉模型：

  • 一日票 / 二日票分别对应哪些 SKU；
  • 如何按 SKU 前缀 LIKE 'Universal Studios Beijing One-Day%' 和 LIKE 'USB%' 区分统计销量；
  • “我是门票助手，会写 SQL 在 MySQL 8.0 上查询”。

关键点：大模型本身不会连数据库，它只是根据这段表结构“生成 SQL 文本”，真正的执行交给工具。

3. ExcSQLTool（第 50–78 行）—— 真正干活的“工具”

@register_tool('exc_sql')
class ExcSQLTool(BaseTool):
    description = '对于生成的SQL，进行SQL查询'
    parameters = [{'name': 'sql_input', 'type': 'string',
                   'description': '生成的SQL语句', 'required': True}]

    def call(self, params: str, **kwargs) -> str:
        args = json.loads(params)
        sql_input = args['sql_input']
        database = args.get('database', 'ubr')
        engine = create_engine(
            'mysql+mysqlconnector://student123:student321@rm-...aliyuncs.com:3306/{database}?charset=utf8mb4',
            connect_args={'connect_timeout': 10}, pool_size=10, max_overflow=20)
        df = pd.read_sql(sql_input, engine)      # 执行查询
        return df.head(10).to_markdown(index=False)  # 只回前10行，防数据过多
  • 注册名 exc_sql：后面 function_list=['exc_sql'] 就是挂这个工具。
  • 入参：大模型产出 JSON 字符串，解析出 sql_input（SQL）和可选 database。
  • 连接：用 SQLAlchemy + mysqlconnector 连阿里云 MySQL；账号密码硬编码在代码里（课程测试库）。
  • 安全护栏：df.head(10) 只返回前 10 行，避免一次返回海量数据把上下文撑爆。

注意 该工具对 SQL 没有任何白名单/只读校验，SELECT 之外的语句也能被执行，仅适合受控的教学环境。

4. init_agent_service（第 81–100 行）—— 组装智能体

llm_cfg = {'model': 'qwen-max', 'timeout': 30, 'retry_count': 3}
bot = Assistant(llm=llm_cfg, name='门票助手',
                description='门票查询与订单分析',
                system_message=system_prompt,
                function_list=['exc_sql'])
  • 使用 qwen-max 模型（擅长数值/统计推理，适合销量统计）。
  • 把 system_prompt 和工具 exc_sql 绑定到 Assistant。

5. app_tui（第 102–144 行）—— 终端交互模式

死循环读用户输入：先问“问题”，再问“可选文件 URL”。空问题会提示重试；带文件则构造多模态消息。 然后 bot.run(messages) 流式执行，把助手回复打印出来并追加进对话历史，实现多轮记忆。

6. app_gui（第 147–169 行）—— 网页交互模式（默认）

启动 WebUI(bot, chatbot_config=...)。其中 prompt.suggestions 预置了 3 个示例问题 （按周统计销量、分省份入园人数、按销售渠道排名），方便一键试用。

7. __main__（第 172–174 行）

if __name__ == '__main__':
    app_gui()          # 默认启动网页界面

想用终端模式，把 app_gui() 改成 app_tui() 即可。

七、关键设计点小结

设计点说明评价
提示词即“数据库字典”把建表语句写进 system_prompt，让模型学会写正确 SQL核心技巧
Function Calling 分离模型只生成 SQL，执行交给工具，职责清晰正确
结果截断 head(10)防上下文溢出，控制返回量必要
多轮历史 messagesTUI 把回复追加进历史，支持追问体验好
SQL 无只读校验工具可执行任意 SQL，含写操作生产需加白名单
DB 凭据硬编码账号密码写在源码里教学可用，生产不可

运行前请确保：① 设置环境变量 DASHSCOPE_API_KEY；② 网络可连通脚本中的阿里云 MySQL；③ 本项目 venv 已安装 qwen-agent[gui]（已修复）。
